# Project review — 2026-10-09

Original review baseline: commit `3e2d18f`. Scope: source code, JavaScript/Python bridge, processing and verification, model installation, Windows process controls, packaging, dependencies, and CI configuration. The initial review did not change production code or dependency versions; the remediation below does. All reproduction inputs were synthetic; no user documents were processed or uploaded.

## Remediation — version 2.1.1

The findings below describe the original review baseline. R1–R5 have now been addressed in the working tree:

- R1: review edits are rejected while busy; exports bind a document revision, reject stale engine results, and recheck the revision under the publication lock after the save dialog. The UI disables editing and output settings while saving, including controls regenerated during navigation.
- R2: every processing gate rehashes installed models and runtime files. GGUF files are checked against the trusted manifest immediately before launching the native runtime. Verification and installation share an inter-process lock.
- R3: 18 artifact sizes are pinned alongside their hashes. Offline imports require complete groups, reject duplicate/oversized entries, check free space, and stage all files before publication. Downloads are bounded and resumable. Failed group publication rolls back; backups survive if disk errors also prevent recovery. The application releases its existing advanced server before replacing model files.
- R4: batch reports use exclusive numbered publication. Empty exports leave existing reports untouched. A failed report write returns the actual saved count and a separate report error.
- R5: Windows native calls have explicit pointer-safe signatures and checked startup results. A startup gate prevents engine initialization until job assignment succeeds. Failed startup cleans up its process and communication handles.

Additional changes: nine compatible dependency upgrades, SHA-pinned GitHub Actions, weekly Dependabot proposals, cancelled superseded builds, a pinned audit tool, explicit test timeouts, isolated advanced-model tests, complete redaction of report value prefixes, private batch reports, UTF-16LE verification, chunked scanning of large image streams, and fail-closed object/stream verification limits. Repeated normalization is shared across targets to limit the cost of scanning large streams. Advanced AI now honors explicit CPU selection and requires sufficient free GPU memory for the selected model. Pixel verification only loads the vision-language model for selected handwritten findings; a missing required handwriting verifier blocks publication. Model fetching also leaves verified runtime libraries in place instead of rewriting libraries that may be in use; paths are resolved before identifying the runtime directory.

New regression coverage is in `tests/test_review_fixes.py`. The real-window smoke test checks that editing is blocked while saving. Final validation results and installer details are recorded at the end of this document.

## Original findings

### R1 — High: edits made during export can be omitted from a saved PDF

Locations: `app/api.py:358`, `app/api.py:371`, `app/api.py:420`, `app/api.py:448`, `app/api.py:485`, `app/ui/app.js:592`.

`_export()` snapshots the findings and remembers the revision. If the findings change, it discards the resulting UI report, but still returns the successful export. `save_pdf()` and `export_folder()` publish those bytes without rejecting the obsolete revision. The UI disables save buttons while saving, but leaves finding controls and manual selection active; the backend mutation methods also accept edits while busy.

Reproduced using the real analysis/export pipeline with a synthetic document and a fake OCR service, injecting a manual mark after the snapshot was taken. Result: `saved=true`, `report=null`, and the newly marked text remained extractable. The fake OCR keeps this reproduction deterministic; this finding concerns publishing the wrong revision, not OCR accuracy. The existing snapshot regression test checks report invalidation but does not check rejection of obsolete publication.

Fix: prevent review mutations during export in both UI and backend, or cancel/rebuild when the revision changes. Check the revision again immediately before publication, including after the save dialog, and bind output settings to the export revision. Add a regression covering the actual saved bytes for single and batch exports.

### R2 — Medium: the processing integrity gate is cached for the entire session

Location: `app/engine/services.py:87`.

`require_integrity()` calls `check_integrity()` only while `_integrity_checked` is unset. After the initial successful check, later calls accept processing without hashing model files again. Runtime files have an additional check before llama.cpp execution, and the normal installer explicitly reloads and checks models; those protections do not cover every model-file change after initialization. In particular, an optional GGUF copied into place after startup can become available without having been part of the original model check.

A mocked verifier reproduction performed one successful check, changed the verifier to raise a tampering error, and called `require_integrity()` again. Processing was accepted and the verifier call count remained one. This demonstrates the cached gate; it is not a demonstrated remote exploit. Exploitation requires a local file change.

Fix: verify optional model files immediately before loading them, and define a practical revalidation policy for processing. Avoid claiming continuous integrity protection when the current policy checks models at startup and installer reload.

### R3 — Medium: offline imports have no size budget and leave partial files on read errors

Locations: `app/engine/models.py:150`, `app/engine/models.py:208`.

Offline ZIP entries are matched against the trusted manifest and checked by hash after extraction, which prevents installing arbitrary contents. However, extraction streams an entry to disk without an uncompressed-size limit, a total installation budget, or a free-space preflight. A recognized entry can consume available disk space before its hash fails. Downloads have the same lack of a maximum byte budget.

A small corrupted ZIP reproduction left a 1,048,576-byte `.part` file after a CRC exception. Cleanup occurs on hash mismatch, but not every extraction or I/O exception. Importing a pack also publishes individual files before the complete group has succeeded, so a failed upgrade can leave a mixed installation.

Fix: pin expected model sizes; enforce byte limits while reading; reject oversized entries before extraction; stage the entire pack; clean temporary files on exceptions; and serialize imports/downloads. Preserve resumable download parts deliberately, while treating failed offline-import parts separately.

### R4 — Medium: batch export replaces an existing verification report

Location: `app/api.py:522`.

PDF collisions are handled using exclusive publication and numbered names. The associated `informe_verificacion.json` always uses `atomic_write()` with its default overwrite behavior. Exporting another batch into the same folder replaces the previous report, including when there are no ready documents. If report writing fails after PDFs have been saved, an uncaught exception prevents returning an accurate partial-success summary.

Fix: give each batch a unique report name or explicitly merge reports without losing prior records. Handle report-write failures and return the actual saved-file count with a distinct report error.

### R5 — Medium: Windows resource controls can fail silently

Locations: `app/engine/worker.py:67`, `app/engine/worker.py:84`, `app/engine/worker.py:232`.

The Job Object wrapper ignores the return values of `CreateJobObjectW`, `SetInformationJobObject`, `OpenProcess`, and `AssignProcessToJobObject`. Missing ctypes argument declarations also leave pointer-sized handles subject to default integer conversions. The worker starts before assignment, leaving an initialization window outside the job. If configuration or assignment fails, processing continues without the promised job protection.

On this machine, querying a newly created job confirmed the expected flags (`0x2100`) and 2 GiB memory limit. This is a failure-path finding, not evidence that the current machine has no memory limit. Python documents default integer argument conversions in its [ctypes reference](https://docs.python.org/3/library/ctypes.html).

Fix: declare native signatures, check every result, report Windows errors, and stop startup safely if required confinement cannot be applied. Gate parsing/model initialization until assignment succeeds. An engine process running under the user's account is crash isolation, not an OS security sandbox against native parser exploitation.

## Additional improvements

Preserve the existing CSP, safe DOM construction, loopback-only AI requests with disabled proxies/redirects, hash-pinned runtime archives, and atomic PDF publication. Add privacy-focused tests for failed verification reports, which currently retain partial values and coordinates. Make verification coverage limits explicit: object traversal stops at a depth of 12, large image streams are skipped after decoding, and residual detection is advisory. These limits need targeted adversarial tests before treating verification as an exhaustive proof of absence.

Broaden the evaluation corpus locally under the applicable data-handling rules, without committing private inputs.
