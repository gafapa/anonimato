# Anonimato

Anonimato is a desktop application that removes personal data, faces, and signatures from PDFs, photos, and scans. It runs on the local computer: documents are not sent to a server. The application removes marked content from both the visible page and recoverable document structures, then verifies the output before saving it.

## Installation

1. Run `AnonimatoSetup-2.2.1.exe` (about 720 MiB). Administrator rights, Python, and CUDA are not required.
2. Open **Anonimato** from the Start menu.
3. Optionally, open **IA avanzada** in the sidebar and choose **Descargar IA avanzada** to enable handwriting recognition and contextual review. The application selects Qwen3-VL-8B (about 5.5 GB) when at least 7 GB of GPU memory is free, or Qwen3-VL-4B (about 2.8 GB) otherwise. Model download is the application's only network connection. It retrieves models from their official source and checks their SHA-256 hashes. On an offline computer, use **Importar paquete sin conexión (.zip)**.

The advanced preference in **Ajustar detección** can prioritize accuracy or memory. Selection is reevaluated at execution time among installed variants; a preference does not download a missing variant. Automatic mode refuses a model that cannot meet its memory budget.

Without a code-signing certificate, Windows may show a SmartScreen warning on first launch. Choose **More info → Run anyway**.

## Usage

1. Add files or folders containing PDF, JPG, PNG, TIFF, or other supported images. You can also drop files into the window.
2. Review the detection summary. Open **Ajustar detección** to change categories or detection methods, then select **Analizar documentos**.
3. Review every page: the marked original appears on the left, the actual output preview in the center, and the findings list on the right. Use ←/→ for pages, J/K for findings, Space to include or exclude a finding, and M to draw a manual redaction.
4. Select **Guardar PDF verificado**. The file is written only if final verification finds no remaining trace of the marked data.
5. If the document will be shared outside your organization, enable **Voy a compartir este documento fuera** before saving. This selects the maximum-security output mode.

## How removal and verification work

- **Layered detection:** validated rules for DNI/NIE/CIF, IBAN/CCC, cards, Social Security numbers, phone numbers, addresses, passports, and IP addresses; GLiNER-PII; PP-OCRv5; optional local handwriting and contextual review with Qwen3-VL; YuNet face detection; and signature detection. Found values and their variants are searched throughout the document.
- **Destructive redaction:** MuPDF removes text, image pixels, and vector drawing beneath each redaction. Content outside the visible page area is also removed.
- **Structural cleanup:** removes Info and XMP metadata, bookmarks, accessibility tags and alternative text, thumbnails, attachments, JavaScript, forms, annotations, application-private data, embedded JPEG EXIF/XMP, earlier revisions, and orphaned objects.
- **Maximum-security mode:** rasterizes every page after redaction. An optional searchable text layer is generated by OCR from the anonymized result.
- **Mandatory verification:** checks the exact bytes that would be saved: document structures, objects and encoded streams, page text (including invisible, off-page, and hidden-layer text), rendered-page OCR, enlarged OCR of redacted areas, handwritten areas when the advanced model is available, faces, and residual rule and AI detection. Failed verification blocks saving and marks the remaining content in red on the page.
- **Process isolation:** each document is analyzed in a separate process with memory limits and hang detection. A damaged or malicious PDF cannot terminate the main window; the engine restarts if needed.
- **Integrity checks:** installed model files and the AI runtime are hashed against the pinned SHA-256 manifest at startup and before each analysis/export. Disk metadata and writable caches are not trusted. Failed checks block processing; registered GGUF files and runtime files are also checked before launching the local AI executable.
- **Protected and signed PDFs:** a password is requested when needed; output is never encrypted. A digital signature cannot survive modification, so the user is warned and signer data is removed.
- **Safe output names and logs:** the default filename is `documento-N_anonimizado.pdf`. CSV/JSON logs omit original values and coordinates unless explicitly requested.

**Limit:** removal is complete for marked content and, in maximum-security mode, for non-visible content. Data missed by both detection and the person reviewing the pages can remain visible. Review every page before sharing.

Export requires working OCR for pixel verification and a working face detector when faces are selected. A missing required verifier blocks saving. Input is limited to 300 MB per file, 512 MB of queued originals, 1,000 pages, and 60 million pixels per image frame or rendered page. Verification reports are invalidated when findings or output settings change. Editing is blocked during export, and the verified revision is checked again before atomic publication, including after the save dialog. Batch reports use unique names and report-write failures retain the actual saved-file count.

Verification scans large image streams in overlapping chunks, including little-endian UTF-16 encodings. PDF structures deeper than 128 levels, more than one million visited object nodes, decoded streams larger than 256 MiB, and unreadable content streams block verification rather than being silently skipped. Residual detection remains advisory; unavailable residual AI checks produce a warning. Verification reports contain no original-value prefixes, and exported reports omit coordinates by default.

## Review improvements in 2.2.1

Choose pending/failed, selected or all documents before analysis. Reanalysis keeps manual areas when source bytes and page geometry match; automatic findings are recalculated. Undo/Redo (`Ctrl+Z`, `Ctrl+Shift+Z` or `Ctrl+Y`) remains in memory only and invalidates verification. The app warns before discarding reviewed unsaved work.

Page zoom supports scrollable inspection. Expand the coordinate editor to create or resize a selected manual area with keyboard-accessible percentage fields. Batch output lists each file's result and report location, and retries only failed entries. **Motores activos** reports actual loaded backends. **Volver a comprobar** retries a blocked integrity check without losing review work.

The [implementation report](docs/improvements-2.2.1.md) records validation and limits. For local synthetic CPU measurement, use `uv run python tools/profile_pipeline.py --threads 4 --output tmp/profile.json`; `ANONIMATO_CPU_THREADS=0` keeps the runtime default. The packaged `component-inventory.json` lists actual payload hashes, embedded native versions and Python license metadata. Unknown native versions/licenses require supplier review.

## Platform qualification

Windows is the primary platform. The 2.2.1 packaged executable passed the local anonymization, integrity and recovery self-test in an empty local profile; installing over an existing application was not tested locally. macOS and Linux use the same application code with platform-specific dependencies. Cross-platform packaging and installation checks are configured in [the build workflow](.github/workflows/build.yml). See [the implementation report](docs/improvements-2.2.1.md) for current validation evidence and its limits.

| | Windows 10/11 x64 | macOS 15+ (Apple Silicon) | Linux x86-64 |
|---|---|---|---|
| Package | `AnonimatoSetup-x.y.z.exe` (Inno Setup, no administrator rights) | `.dmg` containing `Anonimato.app` | `.AppImage` |
| Model acceleration | DirectML | CoreML | CUDA/ROCm with `onnxruntime-gpu`, otherwise CPU |
| Advanced AI (`llama.cpp`) | Vulkan | Metal | Vulkan |
| Isolated engine memory limit | Job Object for the engine and `llama-server` | Hang detection; macOS does not apply per-process memory limits here | `RLIMIT_AS` for the lightweight process |
| Code signing | Optional; SmartScreen may warn | Recommended; unsigned apps may require right-click → Open | Not required |

Build locally with `packaging/build.ps1` on Windows, `packaging/build_macos.sh` on macOS, or `packaging/build_linux.sh` on Linux. macOS signing and notarization use `MACOS_SIGN_IDENTITY`, `APPLE_ID`, `APPLE_TEAM_ID`, and `APPLE_APP_PASSWORD` when provided.

## Development

Install [uv](https://docs.astral.sh/uv/). The project uses Python 3.12, which uv can install on Windows, macOS, or Linux.
Real-window JavaScript coverage also requires Node.js 22 or newer on Windows; the installed application does not require Node.js.

```powershell
uv sync
uv run python tools/fetch_models.py base runtime          # Base models and llama.cpp (Vulkan)
uv run python tools/fetch_models.py advanced              # Optional advanced AI
uv run python -m tests.fixtures.generate                  # Adversarial corpus in tests/fixtures/out
uv run pytest                                             # Rules, leak paths, verification, engine, and UI
uv run ruff check app tools tests                         # Static analysis
uv run coverage run -m pytest && uv run coverage combine && uv run coverage report
uv run python -m app                                      # Open the application
```

- Handwriting OCR benchmark: `uv run python tools/benchmark_handwriting.py` → [docs/benchmark.md](docs/benchmark.md).
- Detection evaluation by category: `uv run python tools/evaluate_detection.py --scanned` → [docs/deteccion.md](docs/deteccion.md). The [2.2.1 expanded synthetic result](docs/detection-evaluation-2.2.1.md) records a held-out seed. Annotated private documents in `eval/docs/*.pdf` with matching `*.json` are excluded by default; opt in with `--private --output tmp/private-evaluation.md`. Private results are aggregate-only and inputs/results are not committed.
- Real-window UI smoke test: `uv run python tools/ui_smoke.py`. Installed executable self-test: `Anonimato.exe --selftest=report.json`. Own handwriting examples go in `eval/own/*.png` with `eval/own/labels.json`; they are not committed.
- Offline advanced-AI package: `uv run python tools/make_offline_pack.py`.
- Windows installer: `powershell -File packaging/build.ps1` → `dist/AnonimatoSetup-2.2.1.exe` (requires Inno Setup 6).
- Critical-module coverage gate: `uv run python tools/check_coverage.py fast-coverage.json`; thresholds are in `packaging/coverage-policy.json`.
- Real-window JavaScript action coverage: `uv run python tools/ui_batch_smoke.py tmp/batch.json --js-coverage tmp/javascript-coverage.json`.
- Installer qualification: compile `packaging/installer.iss` with `/DQualificationBuild=1`, then run `tools/qualify_installer.ps1 -Installer dist/AnonimatoQualificationSetup-2.2.1.exe -ExpectedVersion 2.2.1`. This uses a separate application identity and a fictitious profile under ignored `tmp/`; qualification installers are not release artifacts.

The [2.2.1 verification report](docs/improvements-2.2.1.md) records measured coverage and installer qualification limits.

[docs/pruebas.md](docs/pruebas.md) maps features to tests. The main directories are `app/engine` (processing), `app/ui` (interface), `app/api.py` (JavaScript–Python bridge), `models/manifest.json` (model hashes), `tests/` (adversarial fixtures and tests), and `packaging/` (PyInstaller and installers).

### Security maintenance

Run `uv run pytest tests/test_security.py` for the security regression tests. CI audits installed Python dependencies with `pip-audit`; this does not replace auditing native libraries and bundled AI binaries. Packaged applications verify the original runtime archive before extracting it atomically into a private, versioned user-data directory; executable and library hashes are checked before use. This preserves upstream bytes when packaging tools rewrite or sign native binaries. Linux packaging verifies AppImage tooling against `packaging/build-tools.json`, including cached downloads. If the upstream continuous release changes, the build deliberately stops until the new binary and its hash are reviewed. Windows packaging verifies the WebView2 bootstrapper's Microsoft Authenticode signature and stops on failed build commands.

Keep dependency upgrades within the resolver's compatibility constraints. In particular, the current `tokenizers` requires `huggingface-hub<2.0`, and `sympy` requires `mpmath<1.4`; upgrading those dependencies beyond their supported range requires upgrading their consumers first.

Model sizes are pinned with their checksums. Imports require complete model groups, reject oversized/duplicate entries before extraction, check free space, and stage the entire group before publication. Imports and downloads share an inter-process installation lock with integrity checks. Failed imports remove staging files; interrupted downloads remain resumable in a dedicated cache. Publication failures restore the previous files; if disk errors also prevent rollback, backups are retained for recovery. Limits are 8 GiB per model artifact and 12 GiB per model group, with a 32 MiB free-space reserve. Windows workers wait for successful Job Object configuration and assignment before initializing their engine; failure blocks startup. This contains crashes and resource exhaustion but is not an OS sandbox against native parser exploits.

CI actions are pinned to reviewed commit SHAs, dependency updates are proposed weekly, and superseded branch/PR builds are cancelled. Tests have explicit time limits; advanced inference tests use the isolated engine. The audit tool is pinned to `pip-audit==2.10.1`.
